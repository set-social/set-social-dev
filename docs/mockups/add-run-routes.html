My pick: A, with D as a free bonus

🏃

Option A — additive button on the day itself

The other three all trade something real away:

  • B fights the schema. workout_log_sets is built entirely around reps/load/RPE — every screen that touches it (ActiveExerciseScreen, rest timers, PR detection) assumes that shape. Forcing a GPS-tracked, minutes/km activity through the same pipe means either a special-cased row type everywhere or a second, parallel meaning for the same column — exactly the "duplicate model" trap this app's own docs (docs/social.md) explicitly warn against elsewhere. Keeping cardio as its own cardio_log_entries row is what the whole GPS-tracking feature already assumes.
  • C is a bigger structural commitment than the payoff justifies. The Community tab's post FAB is precedent that this pattern exists in the app, but adding a second global FAB (or overloading the first one with an unrelated "start a workout" menu) is new persistent chrome on every tab, for a feature that's fundamentally about one specific day's plan. It solves "I want to log a run" in general, not "this day already has a plan and I want to add to it" — a different, narrower problem than what was actually asked.
  • D is real but incomplete on its own. Great timing for someone who already finished lifting, useless for someone who wants to run first, or hasn't started the workout yet. It's a good addition to A, never a substitute for it.

A is also the smallest actual build: the button itself is a one-line addition next to "Start Workout" — everything it navigates into (LogCardioScreen, LiveCardioTrackingScreen, Track Live) already exists and needs zero changes. The real work, same as flagged in the last mockup, is teaching WorkoutLogDetailScreen/CompletedWorkoutCard to actually render a cardio session instead of an empty card — which A, D, or any combination of these routes needs regardless of which entry point wins.

Not decided yet: whether D ships alongside A in the same pass or gets deferred — it's cheap once A's underlying "two sessions, one day" rendering fix is in place, so it's more a sequencing question than a design one. Say the word and I'll turn A (+ D if you want it) into a real implementation plan.
